# پلن معماری و اجرایی: پلتفرم برش خودکار ویدیو + دوبله فارسی

## هدف پروژه

یک ابزار داخلی/شخصی (نه SaaS چندکاربره) که این جریان کار را خودکار می‌کند:

1. گرفتن یک ویدیوی یوتیوب با لینک
2. دانلود ویدیو و استخراج صدا
3. تبدیل صدا به متن (STT) با تایم‌استمپ کلمه‌به‌کلمه
4. شناسایی خودکار بخش‌های جذاب برای کلیپ کوتاه (با کمک LLM) + یک مرحله تایید/ویرایش دستی قبل از رندر نهایی
5. برش ویدیو به چند کلیپ کوتاه و ری‌فریم به قاب عمودی ۹:۱۶ برای شبکه‌های اجتماعی
6. ترجمه متن به فارسی
7. دوبله فارسی با یک موتور TTS متن‌باز و خودمیزبان (self-hosted)، با حفظ تا حد امکان صدای پس‌زمینه/موسیقی
8. تولید زیرنویس فارسی (soft-sub و/یا burn-in)
9. رندر خروجی نهایی مناسب اینستاگرام ریلز / تیک‌تاک / یوتیوب شورتس

نکته حقوقی: دانلود و دوبله محتوای یوتیوب ممکن است با ToS یوتیوب و قوانین کپی‌رایت در تضاد باشد. چون این ابزار برای استفاده شخصی/داخلی طراحی می‌شود، مسئولیت رعایت قوانین کپی‌رایت و ToS با کاربر نهایی است؛ توصیه می‌شود این ابزار فقط روی محتوایی استفاده شود که مجوز استفاده دارید یا برای خودتان تحلیل/آرشیو داخلی انجام می‌دهید.

## معماری کلی

چون مقیاس، استفاده شخصی/داخلی است، معماری باید ساده، تک‌سرور و قابل اجرا با Docker Compose باشد؛ نه میکروسرویس پیچیده و نه چندمستأجری.

استک فنی پیشنهادی (Python-first، چون بیشتر ابزارهای AI/ویدیو کتابخانه پایتون دارند):

- API/Backend: FastAPI (پایتون)
- صف کار / پردازش پس‌زمینه: Celery + Redis (هر مرحله پایپ‌لاین یک Task جدا)
- دیتابیس: PostgreSQL (وضعیت Job ها، متادیتای ویدیو/کلیپ، رونوشت‌ها)
- ذخیره‌سازی فایل: دیسک محلی یا MinIO (S3-compatible) برای فایل‌های ویدیویی/صوتی/خروجی
- فرانت‌اند حداقلی: یک داشبورد ساده (Next.js سبک یا حتی Streamlit/Gradio در فاز اول) فقط برای:
  - وارد کردن لینک یوتیوب
  - دیدن وضعیت Job
  - تایید/ویرایش کلیپ‌های پیشنهادی قبل از رندر نهایی (چون گفتی می‌خوای مدل «ترکیبی با تایید دستی» باشه)
  - دانلود خروجی نهایی
- Containerization: Docker Compose با سرویس‌های: `api`، `worker-gpu`، `worker-cpu`، `redis`، `postgres`، (اختیاری) `minio`

### نیازمندی سخت‌افزاری

بخش‌های سنگین (Whisper، جداسازی صدا/موسیقی، TTS) بهتر است روی GPU اجرا شوند. اگر فقط یک GPU در دسترس است، Celery باید طوری تنظیم شود که این تسک‌ها به‌صورت صف‌بندی‌شده و نه هم‌زمان اجرا شوند تا از سرریز VRAM جلوگیری شود (concurrency=1 روی worker-gpu).

## کتابخانه‌ها و مدل‌های پیشنهادی برای هر مرحله

| مرحله | ابزار/مدل پیشنهادی | توضیح |
|---|---|---|
| دانلود ویدیو | `yt-dlp` | پایدارترین ابزار دانلود، به‌همراه متادیتا (عنوان، توضیحات، thumbnail) |
| استخراج/پیش‌پردازش صدا | `ffmpeg` | استخراج WAV مونو 16kHz برای STT |
| تبدیل گفتار به متن | `faster-whisper` (مدل large-v3) | تایم‌استمپ در سطح کلمه، تشخیص خودکار زبان مبدا |
| جداسازی صدا از موسیقی (اختیاری ولی توصیه‌شده) | `Demucs` | برای اینکه در دوبله بتوانیم موسیقی/افکت پس‌زمینه اصلی را نگه داریم و فقط صدای گوینده را با دوبله فارسی جایگزین کنیم |
| تشخیص بخش‌های جذاب (Highlight Detection) | یک LLM (محلی مثل Llama/Qwen از طریق Ollama، یا API مثل Claude/GPT) روی متن رونوشت + تایم‌استمپ | خروجی: لیست کاندید کلیپ‌ها با start/end، امتیاز جذابیت، عنوان و دلیل انتخاب. سپس در داشبورد برای تایید/ویرایش دستی نمایش داده می‌شود |
| برش ویدیو | `ffmpeg` (stream copy در صورت امکان، re-encode در صورت نیاز) | برش دقیق بر اساس تایم‌استمپ تایید‌شده |
| ری‌فریم به ۹:۱۶ | ترکیب تشخیص چهره/سوژه (مثلاً `mediapipe` یا یک مدل ساده object-tracking) + crop پویا؛ fallback به crop مرکزی یا بلور پس‌زمینه | برای اینکه گوینده همیشه در کادر عمودی دیده شود |
| ترجمه متن به فارسی | LLM (همان مدلی که برای Highlight Detection استفاده می‌شود) | ترجمه segment‌به‌segment با حفظ نگاشت زمانی |
| دوبله فارسی (TTS) | `Coqui XTTS v2` (خودمیزبان، متن‌باز، پشتیبانی voice cloning) به‌عنوان گزینه اول؛ `Piper` به‌عنوان گزینه سبک‌تر/سریع‌تر اگر کیفیت صدای کلون‌شده کافی نبود | تولید صدای فارسی برای هر segment؛ سپس time-stretch (با `ffmpeg atempo` یا `pyrubberband`) برای تطبیق با طول segment اصلی |
| میکس صدا | `ffmpeg` | ترکیب صدای دوبله‌شده با ترک موسیقی/افکت جداشده از Demucs |
| زیرنویس | تولید SRT/ASS فارسی از متن ترجمه‌شده + `ffmpeg`/`libass` برای burn-in اختیاری | زیرنویس چسبیده یا soft-sub قابل روشن/خاموش کردن |
| رندر نهایی | `ffmpeg` با پریست هر پلتفرم | 1080x1920, H.264, AAC، بیت‌ریت مناسب هر شبکه اجتماعی |

نکته مهم درباره دوبله: XTTS v2 در حال حاضر از فارسی به‌صورت رسمی پشتیبانی نمی‌کند (زبان‌های پشتیبانی‌شده محدودند)؛ باید در فاز تحقیق فنی (Phase 1) بررسی شود کدام مدل TTS متن‌باز، کیفیت قابل‌قبولی برای فارسی دارد (گزینه‌های قابل بررسی: `Piper` با صدای فارسی موجود در جامعه، فاین‌تیون یک مدل TTS فارسی، یا مدل‌های چندزبانه جدیدتر). این باید به‌عنوان یک ریسک فنی مشخص در پلن ثبت شود تا Claude Code قبل از پیاده‌سازی کامل، یک Proof-of-Concept برای کیفیت صدای فارسی اجرا کند.

## مدل داده (جداول اصلی پیشنهادی)

- `Video`: id, source_url, title, duration, downloaded_path, status, metadata(json)
- `TranscriptSegment`: id, video_id, start, end, text_original, text_fa, speaker(optional)
- `ClipCandidate`: id, video_id, start, end, score, title_suggestion, reason, status(pending/approved/rejected/edited)
- `Clip`: id, clip_candidate_id, video_id, cropped_path, dubbed_path, subtitle_path, final_output_path, status
- `Job`: id, type(download/transcribe/highlight/clip/translate/dub/render), status, error, video_id/clip_id, created_at, updated_at

## جریان پایپ‌لاین (Job-based، هر مرحله یک Celery Task)

```
[لینک یوتیوب]
   -> download_video (yt-dlp)
   -> extract_audio (ffmpeg)
   -> transcribe (faster-whisper) --> TranscriptSegment[]
   -> detect_highlights (LLM) --> ClipCandidate[] (status=pending)
   -> [توقف برای تایید/ویرایش دستی در داشبورد]  <-- کاربر کلیپ‌ها را تایید/ویرایش می‌کند
   -> for each approved ClipCandidate:
        cut_clip (ffmpeg)
        reframe_vertical (face/track + crop)
        separate_audio (Demucs) [صدای گوینده / موزیک پس‌زمینه]
        translate_segment (LLM)
        synthesize_dub (TTS) + time-align
        mix_audio (ffmpeg: دوبله + موزیک پس‌زمینه)
        generate_subtitles (SRT/ASS فارسی)
        render_final (ffmpeg: مرج ویدیو + صدا + زیرنویس + پریست پلتفرم)
   -> خروجی نهایی + متادیتای پیشنهادی (کپشن/هشتگ توسط LLM) در پوشه خروجی/دیتابیس
```

## فازبندی اجرا (برای دادن مرحله‌به‌مرحله به Claude Code)

**فاز ۰ – اسکلت پروژه**
راه‌اندازی repo، Docker Compose (api, worker, redis, postgres)، تنظیمات پایه FastAPI + Celery، مدل‌های دیتابیس، endpoint ساده سلامت سیستم.

**فاز ۱ – دانلود و رونویسی**
پیاده‌سازی `yt-dlp` wrapper، استخراج صدا با ffmpeg، اجرای faster-whisper، ذخیره TranscriptSegment در دیتابیس. تست روی چند ویدیوی نمونه.

**فاز ۲ – تشخیص کلیپ + داشبورد تایید**
پرامپت LLM برای تحلیل رونوشت و پیشنهاد ClipCandidate ها، ساخت داشبورد حداقلی برای مرور/ویرایش/تایید کلیپ‌ها (این مرحله برای مدل «ترکیبی با تایید دستی» حیاتی است).

**فاز ۳ – برش و ری‌فریم عمودی**
برش دقیق ویدیو بر اساس کلیپ تاییدشده، پیاده‌سازی الگوریتم ری‌فریم به ۹:۱۶ (شروع با crop مرکزی ساده، سپس ارتقا به تشخیص سوژه).

**فاز ۴ – ترجمه و دوبله**
Proof-of-concept کیفیت TTS فارسی (ریسک فنی اصلی پروژه)، پیاده‌سازی ترجمه segment‌به‌segment، سنتز صدا، تطبیق زمانی (time-stretch)، جداسازی و میکس موسیقی پس‌زمینه.

**فاز ۵ – زیرنویس و رندر نهایی**
تولید SRT/ASS فارسی، گزینه burn-in، رندر نهایی با پریست‌های اینستاگرام/تیک‌تاک/یوتیوب شورتس، تولید پیشنهاد کپشن/هشتگ.

**فاز ۶ – بهبودهای بعدی (اختیاری، بعد از MVP)**
- آپلود خودکار به شبکه‌های اجتماعی از طریق API رسمی هرکدام
- صف پردازش دسته‌ای (چند ویدیو هم‌زمان)
- انتخاب چند voice برای دوبله
- آنالیتیکس ساده روی کلیپ‌های تولیدشده

## نکات مهم برای Claude Code هنگام پیاده‌سازی

- شروع با یک اسکریپت خطی (CLI ساده، بدون FastAPI/Celery) برای تست کل زنجیره روی یک ویدیوی نمونه توصیه می‌شود؛ بعد از اطمینان از درست‌کارکردن هر مرحله، آن را به Job/Task تبدیل کنیم.
- قبل از سرمایه‌گذاری روی XTTS/Piper برای فارسی، حتماً یک تست کوچک کیفیت صدا انجام شود (ریسک فنی اصلی).
- مدیریت خطا در هر Task باید مستقل باشد؛ اگر دوبله یک کلیپ خاص شکست خورد، نباید کل پایپ‌لاین ویدیو متوقف شود.
- چون فایل‌های ویدیویی حجیم هستند، پاکسازی دوره‌ای فایل‌های موقت (audio خام، فایل‌های جداشده Demucs و ...) باید از همان فاز ۰ در نظر گرفته شود.
- لاگ‌گیری واضح روی هر مرحله (به‌خصوص زمان اجرای STT/TTS/Demucs که سنگین‌ترین بخش‌ها هستند) برای دیباگ لازم است.
